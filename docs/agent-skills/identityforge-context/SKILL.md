# IdentityForge Context

## Orient to the project

- Treat IdentityForge as an actively evolving, portfolio-grade Identity and Access Management platform focused on identity, authentication, authorization, and enterprise IAM capabilities.
- Recognize that the project is early-stage and intentionally improving; do not infer production readiness or treat every existing design as permanent.

## Consult the sources of truth

- Read `README.md` for the project introduction, implemented capabilities, high-level architecture, local workflows, and stated limitations.
- Read relevant files under `docs/` for detailed architecture, design decisions, and technical references.
- Read current roadmap documents, including `docs/ROADMAP.md`, for priorities, known limitations, and future direction.
- Re-check these sources when a task depends on project details instead of relying on this skill as a substitute for documentation.

## Preserve the documentation boundary

Keep project explanation in `README.md`, detailed technical knowledge in `docs/`, and Codex reasoning guidance in skills.
